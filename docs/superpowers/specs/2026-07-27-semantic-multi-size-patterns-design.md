# Fuse Bead Designer 语义多尺寸设计

## 目标

在不牺牲主体身份、含义和关键结构的前提下，为同一参考图提供不同制作成本的拼豆设计图。

多尺寸不是固定倍率缩放或低采样率降采样。每个有效版本都是基于同一参考图、基准版和语义特征契约完成的独立像素重设计，再由确定性编译器生成网格、数量和底板信息。

## 产品原则

1. 细节完整是硬门槛，尺寸、珠数和底板数默认是软目标。
2. 默认只生成一份基准版，避免用户未表达多尺寸需求时浪费图像生成、编译和复核资源。
3. 用户明确要求多尺寸、不同成本或底板比较时，直接生成多版。
4. 普通单版交付后，简短询问用户是否需要多版参考。
5. 不强制交付固定数量的版本。无意义、失真或差异过小的档位应取消或合并。
6. 先确定图案，再计算29×29底板布局；底板不能反向决定或压缩图案尺寸。
7. 图像模型负责语义重绘，确定性编译器负责坐标、色板映射、数量、底板和最终模板。

## 默认交互

### 普通请求

当用户只要求生成拼豆设计图时：

1. 完成输入识别、主体处理、语义特征提取和基准版生成。
2. 编译并交付基准版及其材料信息。
3. 在交付结尾询问：

> 是否需要我基于同一核心特征，再生成轻量版、均衡版和精细版供你比较？各版本会独立重绘，尺寸可自动调整，不会为了缩小而机械降采样。

询问不得阻塞基准版交付。

### 明确的多尺寸请求

当用户在初始请求中提到“小中大、多尺寸、不同预算、控制珠数、比较底板”等意图时，跳过交付后的询问，直接执行多尺寸流程。

### 明确的分阶段请求

用户可以要求“先生成基准版，再决定是否生成其他尺寸”。此时必须在基准版交付后停止，等待确认。

## 版本定义

| 版本 | 目标 |
| --- | --- |
| 轻量版 | 保住全部硬特征的最低可行制作成本 |
| 均衡版 | 细节、珠数、底板和制作难度的推荐平衡点 |
| 精细版 | 在仍低于或不超过基准版复杂度的前提下保留更多软特征 |
| 基准版 | 首次交付、最接近参考图核心语义和主要细节的设计 |

“基准版”是默认通用名称。只有输入本身存在可机械验证的原生逻辑网格，并且该网格没有发生语义改写时，才可以称为“原网格版”或“原版”。

## 通用语义特征契约

插件不得预设图片一定是人物，也不得把“眼睛、高光、饰品”等人物特征写成通用验收规则。

每个任务先根据实际内容生成一份专属的语义特征契约。契约中的每个特征至少包含：

- 标识和简短名称；
- 特征类型；
- 它为何决定主体身份、用途、含义或构图；
- 在原图和基准版中的位置；
- 重要性：`hard` 或 `soft`；
- 与其他特征的连接、包含、对称、顺序或相对位置关系；
- 可辨认的最低表达条件；
- 各版本的验收结果和失败原因。

### 特征类型示例

- 人物或动物：脸部结构、姿态、毛发轮廓、服饰和辨识性配件。
- 普通物体：整体比例、关键部件、孔洞、把手、边缘转折和连接关系。
- Logo、文字或符号：可读性、笔画连通、负空间和几何比例。
- 建筑或风景：天际线、主体层级、地平线和主要色块关系。
- 植物：枝干结构、叶片方向、花朵层次和不对称特征。
- 抽象图案：对称性、重复节奏、主几何形状和颜色分区。
- 多主体画面：主体数量、相对位置、遮挡顺序和必要负空间。

这些类型只帮助识别，不是固定模板。最终契约必须来自当前图片。

### 重要性

- `hard`：丢失后会改变主体身份、用途、文字含义、主要构图或识别结果。
- `soft`：可以简化的纹理、渐变、次要装饰和微小色差。
- 当前预算无法表达的硬特征不能被降级为软特征。应扩大尺寸、取消该档或向用户说明冲突。

## 多尺寸生成算法

### 共同输入

每个版本同时参考：

1. 原始图片；
2. 已通过验收的基准版；
3. 同一份语义特征契约；
4. 同一套用户色板或品牌库存约束。

禁止采用“基准版缩成精细版，再缩成均衡版，再缩成轻量版”的串行链路，避免结构误差和语义漂移逐级累积。

### 尺寸规划

1. 根据主体长宽比、硬特征数量、最细必要结构、负空间和内容复杂度，估算最低可行逻辑网格。
2. 在最低可行尺寸和基准版尺寸之间规划轻量、均衡和精细三个软目标。
3. 目标尺寸不要求是29的倍数，也不使用全局固定锚点作为硬限制。
4. 用户给出的珠数或底板数默认是软目标；只有用户明确要求硬上限时才作为硬约束。

### 独立重绘与验收

每个档位：

1. 从原图、基准版和语义契约独立创建语义像素草稿。
2. 使用硬边缘和单格平色，不使用固定倍率、平均采样、中位色采样或其他机械降采样生成最终设计。
3. 检查全部硬特征、关键连接、比例、负空间、文字可读性和主要色块关系。
4. 每档总计最多生成两个候选：一个初始候选，以及失败后扩大逻辑网格生成的一个重试候选。
5. 重试候选仍失败则取消该档，不交付失真版本。

### 档位合并

如果扩容后的相邻版本在逻辑尺寸、珠数和保留细节上没有实质差异，应合并档位。最终允许输出2至4个有效版本，不为凑齐“小中大原”而重复交付。

### 调色板

所有版本默认使用同一色板定义和相同颜色ID，便于用户比较和采购；不同版本可以使用该色板的不同子集。用户提供品牌或库存色板时，所有版本都必须遵守，不得虚构品牌色号。

## 输入类型差异

### 成品拼豆照片

- 基准版先排除手、工具、桌面、反光、阴影、板孔和背景，校正透视并恢复可验证原网格。
- 如果基准版没有发生语义重构，可以为 `verified`。
- 多尺寸版本属于重新设计，必须重新进行语义验收，不能继承基准版的 `verified`。

### 原生像素画

- 基准版保留并机械验证原逻辑像素。
- 多尺寸版本不得直接使用普通图像降采样；它们是基于原图与特征契约的语义派生版本。

### 高清照片或插画

- 先创建基准语义草稿，不能把连续图像直接采样成最终网格。
- 基准版与多尺寸版都包含设计决策，不能标记为 `verified`。

### Logo、文字和抽象图形

- 可读性、笔画连通、负空间和几何关系优先于色彩微差。
- 尺寸不足时扩大或取消档位，不输出不可读版本。

## 验证状态

- `verified`：只用于没有语义改写的可验证原网格。
- `inferred-low`：只用于范围明确、结构唯一且逐格记录的少量遮挡补全。
- `review-required`：用于语义重绘、存在设计取舍或核心遮挡仍需确认的版本。

编译器数量准确不等于语义内容已经确认。任何语义重绘版本都不得仅因计数一致而升级为 `verified`。

## 失败与停止条件

- 多个主体都可能是用户目标：先询问用户选择。
- 核心遮挡存在多种合理补全：请求更清晰图片、其他角度或用户选择。
- 硬珠数/底板上限与硬特征冲突：报告不可同时满足，不交付失真图。
- 某档两次扩容后仍不合格：取消该档。
- 相邻档差异过小：合并。
- 主机缺少必要图像能力且输入不能直接编译：停止，不伪造草稿。

## 数据流与产物

### 共享中间数据

- 清理或校正后的主体；
- 基准语义草稿；
- 语义特征契约；
- 色板定义；
- 遮挡和推断区域。

共享的是分析结果和约束，不是缩放后的像素。

### 每版产物

- `template.png`
- `colors.csv`
- `pattern.json`
- `report.json`
- `review.png`
- 特征验收结果

多版交付额外生成：

- 对比图；
- 机器可读汇总，包含尺寸、珠数、底板、验证状态和保留特征；
- 推荐说明，默认指出均衡版，但不替用户做不可逆的材料选择。

所有数量都必须来自各版本独立编译后的 `pattern.json`，不能按基准版比例估算。

## 资源与时延控制

- 默认只生成基准版。
- 用户确认多版后，复用主体识别、干扰处理、语义契约和色板，不重新执行整套输入分析。
- 每个档位最多生成两个语义候选，不进行第三轮重绘。
- 已取消或合并的档位不继续编译。
- 不重复执行与成稿无关的全量验证。

## 验证策略

### 确定性验证

- 网格宽高与行列一致；
- 逐色数量、总珠数和CSV一致；
- 底板布局由图案尺寸推导；
- 输出文件可读取；
- 遮挡和推断格与审查图一致；
- 多档位珠数和复杂度关系合理，但不要求固定比例。

### 语义验证

- 每个硬特征均有明确通过或失败结果；
- 比例、连接、包含、对称、顺序和负空间关系仍成立；
- 文字、Logo和符号仍可辨认；
- 取消或扩容决策有原因记录。

### 评估样例

至少覆盖：

- 人物或动物；
- 普通物体；
- Logo或文字；
- 建筑或风景；
- 植物或抽象图案；
- 有手、反光、背景或遮挡的成品拼豆照片。

验收不使用整图像素完全一致作为通用标准。基准版和多尺寸版的语义契约、编译一致性和人工可辨认结果共同构成验收证据。

## 非目标

- 不保证每次都输出固定四版。
- 不以29×29底板倍数作为图案生成尺寸。
- 不为缩小而自动删除硬特征。
- 不让图像模型生成数量、图例、坐标或验证结论。
- 不把重新设计的版本冒充原作品的精确还原。
